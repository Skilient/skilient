# Prompts for W6 to W10

Written 2026-11-26, after W3 to W5. Each prompt is the **shared block** followed by one or more **workstream blocks**. Paste them as one message into a fresh session on branch `azure`.

## How to run them

- **One session at a time.** Five sessions in parallel would fight over the same shared files (`packages/contracts/events.json`, `perf/budgets.json`, `packages/host/src/registry.ts`, `docs/decisions.md`, `CLAUDE.md`, `docs/azure/journey-handoff.md`) and the 7 GB of memory the test containers need.
- **Two sessions, not one.** W3 to W5 (about 15,000 lines of SQL) filled one long session and hit usage limits twice. W6 to W10 is about 18,000 lines. Suggested split:
  - Session 1: shared block + **W9, W8, W6**, in that order.
  - Session 2: shared block + **W7, W10**.
- **Why this order.** The PRD allows any order between W3 and W12, because services meet through events and ports. But W9 (notify and media) clears the most hand-off to-dos already waiting in W1 to W5; W8 (credentials) issues the Record entries that ranking's formula v2 scores, so W6 after W8 can test against real events instead of hand-made ones; W10 (trust) touches every service (sanctions, moderation, config, analytics), so it goes last, when the services it reaches exist.
- If you prefer one workstream per session, paste the shared block plus that one block.

## Lessons from W3 to W5 (already reflected above)

- `buf lint` wants a request and response message of its own for every RPC; sharing them failed `contracts:check` at the end of W5 and cost a rename of 36 methods.
- Test titles that contain `<service>.spec` trip the no-foreign-schema lint.
- Goldens: record twice, keep stable cases, ids as types; wrap golden calls with named arguments.
- Foreign keys with cascades must match what the recorded behaviour shows (W5's disconnect).
- Under full-suite load, a 20 s web unit test and a budget test's container connection each failed once and passed alone.
